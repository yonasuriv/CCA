# CCA 1.0.0 Release Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring the current tested CCA repository from draft/release-candidate documentation quality to a coherent, mechanically guarded 1.0.0 release without changing the established ontology or Hybrid v2 behavior.

**Architecture:** Keep `skills/cca/references/core/` as normative authority and treat repository docs/publications as projections of that authority. Add release-readiness regression checks to the existing validation layer, fix the public/documentation surfaces they expose, then update version/status/citation metadata consistently and run the complete existing gates on the exact branch head.

**Tech Stack:** Markdown, CFF/YAML, Python 3.12 `unittest`, existing `.github/scripts/validate_repo.py`, GitHub Actions.

**Spec:** `skills/cca/references/core/spec.md`

## Global Constraints

- Do not redesign CCA semantics, roles, axes, bindings, compatibility vocabulary, or Hybrid Workspace v2 behavior.
- `skills/cca/` remains the self-contained installable distribution and normative runtime authority.
- Preserve the frozen Hybrid v1 baseline plus the existing v2 `reference.curated` / `reference.collected` extension.
- Normalize product identity to “interoperability architecture”; use “layer” only descriptively, not as the primary product type.
- A 1.0.0 release must not retain draft placeholders, stale Hybrid-v1-current claims, malformed references, or incomplete current package maps.
- Existing validation gates must continue passing.
